# デプロイの大きさの調査（2026-10-01）

Vercel の無料枠の Deployment Storage（10GB）を超えたため、1回のデプロイの大きさと、ブランチの片づけ方を調べた結果です。
**この PR ではサイトのコード・設定は変えていません**（変えるのは確認のあと）。

## 1. `npm run build` の出力（`dist/`）

- 全体: **73MB**・520ファイル（HTML 513・XML 3・PNG 1・SVG 1・JS 1・txt 1）
- 画像は `og-default.png`（192KB）の1枚だけ。カード画像は外部の URL を読んでいるので `dist/` に入らない → **画像の重複はなし**

| フォルダ・ファイル | 大きさ | 中身 |
|---|---|---|
| `dist/cards/` | 58MB | カードページ 約430本（1本 約130〜180KB） |
| `dist/columns/` | 9.4MB | デッキ記事 約55本（1本 約170KB）＋一覧 318KB |
| `dist/index.html` | 2.7MB | トップ（全カード約400枚の一覧を1ページに出している） |
| `dist/blog/` | 1.5MB | コラム記事 |
| `dist/tags/` | 952KB | タグページ |
| `dist/og-default.png` | 192KB | OG 画像 |
| その他 | 1MB 未満 | tier・about・privacy・404・sitemap・rss など |

### 1ページが大きい理由

`astro.config.mjs` の `build: { inlineStylesheets: 'always' }` で、**Tailwind の CSS（約80KB）を全ページの HTML に埋め込んでいる**。
カードページ 1本 178KB のうち 80KB が `<style>`。513ページ分で **約40MB が同じ CSS のくり返し**。

試しに `inlineStylesheets: 'never'`（CSS を `_astro/*.css` の1ファイルにしてすべてのページで共有）でビルドすると、
**73MB → 36MB（約半分）** になった（CSS は 82KB の1ファイル。ブラウザは1回読めば2ページ目からはキャッシュを使う）。

### 公開しなくていいファイル

- `public/generate-assets.html`（36KB）… X 用画像を作るための道具のページ。`noindex, nofollow` は付いている。小さいので容量への影響はほぼないが、公開しなくてよいなら `scripts/assets/` に移せる（`render-x-assets.js` の読み込み先の変更が必要）
- それ以外（`.map`・`.DS_Store`・元データの JSON など）は入っていない

## 2. 容量が増えている本当の理由：デプロイの回数

Vercel は**デプロイ1回ごとに、そのときの `dist/` を丸ごと保存**する（古いデプロイも消すまで残る）。

- main への取り込み（本番デプロイ）: 9/28〜10/1 の4日で約50回（価格更新の自動コミットを含む）
- そのほかに、ブランチに push するたびにプレビューのデプロイができる（`auto/*`・`claude/*`・`feat/*` など）
- 73MB × 約140回 ≒ 10GB なので、数日で上限に届く

## 3. 減らす案（おすすめ順。実際に変えるのは確認のあと）

1. **Vercel の設定で古いデプロイを自動で消す**（コード変更なし・効果がいちばん大きい）
   - Vercel のプロジェクト → Settings → Security の「Deployment Retention Policy」で、プレビュー・本番とも保存期間を短く（例: 1週間〜1か月）する
   - 今たまっている分は、Deployments の一覧から古いもの（特にプレビュー）を選んで削除する。本番の今のデプロイと、ロールバックに使うかもしれない直近の数件は残す
2. **CSS をページに埋め込まず1ファイルにする**（`inlineStylesheets: 'always'` → `'auto'` か `'never'`）
   - 1回のデプロイが 73MB → 約36MB
   - 気になる点: 最初の1ページの表示で CSS を1回余分に読む（82KB。2ページ目以降はキャッシュ）。Lighthouse の数字を前後で比べてから決める
3. **トップページの全カード一覧を軽くする**（2.7MB）
   - 例: 最初は数十枚だけ HTML に出して、残りは「もっと見る」/ カードページの一覧へ。容量への影響は小さい（全体の約4%）が、スマホでの表示も速くなる
4. **プレビューのデプロイを作らないブランチを決める**（任意）
   - 例: 価格更新など、見た目が変わらない自動コミットはデプロイを省く（Vercel の「Ignored Build Step」）。ただしプレビューを見てからマージする運用なので、PR のブランチのプレビューは残す

## 4. ブランチの片づけ

- **マージ後のブランチの自動削除は、GitHub の設定画面で済む**（Actions は不要）
  - リポジトリ → Settings → General → 「Pull Requests」の **「Automatically delete head branches」** にチェック
  - GitHub Actions が作る PR（`auto/deck-sync` など）も、マージされればブランチが消える。次の実行で同じ名前のブランチが作り直されるので、自動生成は今まで通り動く
- 取り込み済みのブランチの一覧と削除は、PR の本文を参照
